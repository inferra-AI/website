Questions, answered.

Inferra in plain words.

What is Inferra?

Inferra is the Git-native cloud: a PaaS that builds APIs, web apps and background workers from GitHub pushes with Cloud Native Buildpacks and runs them with managed Postgres, a Redis-compatible Valkey cache and S3 buckets. Connect a GitHub repository and push; Inferra runs the servers, HTTPS, scaling and patching.

How is Inferra different from Vercel?

Vercel is built mainly for frontends and short serverless functions. Inferra runs long-running services and background workers with no function timeouts, keeps the database next to the app instead of at another vendor, and charges a flat monthly price instead of usage-based billing.

Is Inferra a Heroku alternative?

Yes. Like Heroku, you deploy with git push and buildpacks, with managed Postgres. Inferra adds a preview copy of your apps for every branch, a gVisor sandbox around every app on every plan, and flat pricing with Postgres, cache and buckets included.

Do I need a Dockerfile or Kubernetes knowledge?

No. Buildpacks detect your language and build a secure image from source. Inferra runs the servers, clusters, HTTPS, scaling and patching, so you only maintain your code.

Which languages and frameworks are supported?

Node.js, Python, Go, Java, Ruby, PHP, .NET and static sites, plus any app with a Procfile.

Can I run background workers?

Yes. An app with a start command and no port runs as a long-running background worker, next to your web apps and sharing their databases.

How does pricing work?

Plans are flat: a Free 7-day trial, Pro at $20 a month and Team at $99 a month. When you reach a plan limit, the next push stops; nothing is added to your bill automatically.

How are apps isolated and secured?

Every app runs in its own gVisor sandbox on every plan, including Free. Each environment is a private network, and a database accepts connections only from the apps that use it.

Does Inferra work with AI coding assistants?

A hosted MCP server is coming soon: assistants such as Claude, Codex, VS Code and Cursor will read logs and metrics to explain problems, and propose configuration changes as pull requests you review.

Security and data handling

Inferra isolates apps with gVisor, controls network access by space and service binding, and keeps secret values out of read APIs. This page describes the implemented controls and preview limits.

Sandbox and builds

Every app on every plan, including Free, runs in a gVisor sandbox. Spaces use separate namespaces and network policies. Buildpacks come from a mirrored catalog pinned by digest. The platform builds source with buildpacks; the org.yaml parser has no Dockerfile option.

Network rules

TrafficRule on every plan
InboundThrough Inferra’s HTTPS gateway on port 443, forwarded to the app’s PORT.
Within a spaceApps in the same space can reach each other.
OutboundAny public port, including external databases, SMTP and APIs. Private ranges and cloud metadata are blocked.
Managed Postgres and cacheOnly apps bound to the service can connect.
BucketsApp pod identity grants access; bucket keys are not handed to apps.

Secret values are write-only

Runtime variables and secrets are encrypted in the platform database with AES-GCM. Apps receive a versioned environment; switching versions rolls running instances. The API does not return secret values. Service connection values also stay hidden, including when a developer reveals ordinary environment variables.

The GitHub App reads variables and secret names, not secret values. Values reach Inferra through an explicitly configured environment workflow or a dashboard write. Read the current-release workflow caveat before committing a generated workflow. Applications can still print their own secrets; keep credentials out of logs and public issue reports.

Deletion and the restore window

Removing a service’s final app declaration schedules deletion. Postgres backup configuration retains backups for 7 days; restoration is an Inferra staff operation into the original space and depends on usable retained backups. The restore path and timing still need verification on the development platform. Contact support through the website issue tracker promptly after an accidental deletion, without including credentials.

Removed buckets retain data for 7 days before cleanup. A removed cache has no restore retention. Do not assume application disks, cache contents or a deleted org are recoverable.

Free is a 7-day trial: apps stop at expiry. Unless you upgrade, data cleanup follows 7 days later. Trial purge bypasses normal service retention; the normal restore window does not extend the trial. Removing the GitHub App’s access to a repository also initiates org cleanup.

Report a vulnerability

Use a private GitHub security advisory on inferra-AI/website. If private reporting is unavailable, open an issue asking for a private reporting channel; do not include exploit details, private data or credentials in a public issue.

Inferra does not hold SOC 2 or ISO 27001 certification. We do not claim HIPAA certification or a compliance guarantee for your application.

Security and data handling

Inferra isolates apps with gVisor, controls network access by space and service binding, and keeps secret values out of read APIs. This page describes the product controls and data retention.

Sandbox and builds

Every app, including apps covered by the free allowance, runs in a gVisor sandbox. Spaces use separate namespaces and network policies. Buildpacks come from a mirrored catalog pinned by digest. Apps build from source with buildpacks, with no Dockerfile option. Every successful build is submitted for vulnerability scanning. A scan may be incomplete or unavailable; check its result before treating an image as scanned.

Build vulnerability scanning

The build image’s software bill of materials (SBOM) supplies the package inventory for scanning. The core API accepts pass, warn and block verdicts tied to that exact image digest. A warning is not a clean bill of health; a blocking verdict prevents deployment when an opt-in blocking policy is active.

The current orgfile parser supports this policy in version 1 only:

version: 1
scan:
  block: critical

critical is the only accepted nonempty value. high is rejected, and v2 org.yaml does not accept the scan field. Keep the rest of your valid v1 configuration when adding this setting.

No SBOM or an inventory that cannot be scanned means the scan is incomplete, not a pass. Without a blocking policy, the core permits deployment and records Security scan: not scanned when no verdict is available. With block: critical, it waits for a verdict; a block result or expiry of the two-minute scan deadline fails deployment. A returned warn verdict is allowed even under that policy. The scanner determines how an incomplete inventory becomes a verdict; core code alone does not guarantee that every incomplete scan is blocked.

See the GitHub commit status inferra/scan/APP for the verdict and critical/high counts, and follow its report link when supplied. Deployment warnings and errors are also returned by the API. The current dashboard Deployments table has no detailed scan-results panel; use the commit status for results.

The reviewed core code delegates vulnerability matching to a separate scanner service. It does not identify OSV as the vulnerability source.

Network rules

TrafficRule for every app
InboundThrough Inferra’s HTTPS gateway on port 443, forwarded to the app’s PORT.
Within a spaceApps in the same space can reach each other.
OutboundAny public port, including external databases, SMTP and APIs. Private ranges and cloud metadata are blocked.
Managed Postgres and cacheOnly apps bound to the service can connect.
BucketsApp pod identity grants access; bucket keys are not handed to apps.

Secret values are write-only

Runtime variables and secrets are encrypted in the platform database with AES-GCM. Apps receive a versioned environment; switching versions rolls running instances. The API does not return secret values. Service connection values also stay hidden, including when a developer reveals ordinary environment variables.

The GitHub App reads variables and secret names, not secret values. Values reach Inferra through an explicitly configured environment workflow or a dashboard write. Read the selected-secret workflow before committing a generated workflow. Applications can still print their own secrets; keep credentials out of logs and public issue reports.

Deletion and the restore window

Removing a service’s final branch-file binding schedules deletion. Postgres backup configuration retains backups for 7 days; restoration is an Inferra staff operation into the original space and depends on usable retained backups. Contact support through the website issue tracker promptly after an accidental deletion, without including credentials.

Deleting a named branch retains Postgres restore eligibility and bucket data for 7 days. Pattern branches delete service instances immediately. A removed cache has no restore retention. Do not assume application disks, cache contents or a deleted org are recoverable.

The first $5 of usage every month is free per account, with a card on file. At $0, new deploys pause immediately; after a 3-day grace period, workloads pause. Data is kept for 7 days, and a top-up restores operation. Removing the GitHub App’s access to a repository also initiates org cleanup.

Report a vulnerability

Use a private GitHub security advisory on inferra-AI/website. If private reporting is unavailable, open an issue asking for a private reporting channel; do not include exploit details, private data or credentials in a public issue.

Inferra does not hold SOC 2 or ISO 27001 certification. We do not claim HIPAA certification or a compliance guarantee for your application.

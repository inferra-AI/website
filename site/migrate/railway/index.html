→

On Inferra

.inferra/org.yaml
version: 2
apps:
  - folder: api
    branches: [main, feature/*]
services:
  postgres:
    - name: orders
      storage: 10Gi
.inferra/main.yaml
apps:
  api:
    run:
      port: 3000
    health:
      path: /health
    services: [orders]

Put the service in its own folder (here, api/). It gets its database address as ORDERS_URL. Your server must listen on 0.0.0.0 and the PORT it's given, and answer /health. Inferra reads these two files, not railway.json. Previews for feature/* branches use a .inferra/feature.yaml in that branch; start by copying main.yaml. Configuration reference

What changes

Three things work differently.

Railpack build

Inferra detects the runtime with buildpacks; test that dependencies install.

Start and health check

Use package.json or a Procfile, and health.path.

Project services and variables

Declare services in org.yaml and bindings in main.yaml; add secret values separately.

The move

Five steps. Your Railway app keeps running until the last one.

  1. Connect your repoInstall the Inferra GitHub App and pick the repo.
  2. Add the two filesCommit .inferra/org.yaml and .inferra/main.yaml. Push to main.
  3. Set your secretsCommit only the names. Add the values in the dashboard.
  4. Copy your databaseTest a restore and check row counts. Then pause writes, take the final pg_dump and restore it from an app bound to orders (Postgres is private).
  5. Switch your trafficKeep writes frozen on Railway from the final copy until users are on the new URL, and stop its workers and schedulers. Check pages, sessions, jobs and data, then switch. To roll back after new writes, copy that data back first.
Copy the databaseexample
# 1. On a machine that can reach your current database
pg_dump --format=custom --no-owner --no-acl "$SOURCE_DATABASE_URL" > app.dump

# 2. In an Inferra app bound to the database, with app.dump copied there
pg_restore --no-owner --no-acl --exit-on-error --dbname="$ORDERS_URL" app.dump

Postgres on Inferra is private, so run the restore from an app bound to the database. Move the dump over a route you control and never commit it. Check the Postgres version and extensions match before the final copy.

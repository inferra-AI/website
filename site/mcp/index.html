Inferra · Reference

Connect your assistant to Inferra

Inferra’s MCP server connects Claude Code, Codex, Cursor and VS Code to your apps. Read logs, metrics and deployment status, explain failures, and draft configuration changes for review.

Create a token and choose your client

Create a personal API token in the Inferra dashboard. Replace <host> with your Inferra MCP server host and <token> with your token. Use the MCP server address, rather than assuming the core API host serves MCP. The connection uses Streamable HTTP.

Claude Code

claude mcp add --transport http inferra https://<host>/mcp --header "Authorization: Bearer <token>"

Codex

Set INFERRA_TOKEN in your environment, then add this to ~/.codex/config.toml:

[mcp_servers.inferra]
url = "https://<host>/mcp"
bearer_token_env_var = "INFERRA_TOKEN"

Or use the CLI:

export INFERRA_TOKEN=<token>
codex mcp add inferra --url https://<host>/mcp --bearer-token-env-var INFERRA_TOKEN

Cursor

Set INFERRA_TOKEN in the environment available to Cursor. Put this in ~/.cursor/mcp.json or your project’s .cursor/mcp.json:

{
  "mcpServers": {
    "inferra": {
      "url": "https://<host>/mcp",
      "headers": {
        "Authorization": "Bearer ${env:INFERRA_TOKEN}"
      }
    }
  }
}

VS Code

Put this in .vscode/mcp.json. VS Code prompts for the token so you do not commit it:

{
  "inputs": [
    {
      "type": "promptString",
      "id": "inferra-token",
      "description": "Inferra personal API token",
      "password": true
    }
  ],
  "servers": {
    "inferra": {
      "type": "http",
      "url": "https://<host>/mcp",
      "headers": {
        "Authorization": "Bearer ${input:inferra-token}"
      }
    }
  }
}

If your client rejects a configuration, check its remote HTTP server configuration with headers.

Available tools

ToolWhat it does
list_orgsList orgs you belong to, their status and repository.
list_spacesList an org’s spaces and their branches.
list_appsList apps with state, URL and current deployment.
app_statusRead app conditions, instances, restarts, last exit and deployment.
get_logsRead runtime logs; filter by since, grep, instance and limit.
get_metricsRead latest, minimum, maximum and average metrics per series, plus CPU and memory limits.
list_deploymentsList deployments, newest first.
explain_failed_deploymentRead the failed deployment, error, build log tail, runtime logs, instances and recent events together.
get_org_yamlRead the org.yaml applied at the synced commit.
propose_config_changeGet advisory validation and a unified diff for proposed org.yaml; writes nothing.

The resource inferra://docs/org-yaml provides an org.yaml reference. Try asking: “Explain the latest failed deployment for my API” or “Show its recent logs and CPU usage.”

Your token, your permissions

All MCP tools are read-only. Every request verifies your token with the core API, and tool calls use that same token and your permissions. Revoking it stops access on the next request. The server has no privileges of its own.

propose_config_change does not write to Inferra or GitHub. Your assistant can use its own repository access to open a pull request for you to review. Merging and pushing follows the normal deployment flow.

Tokens are not logged or sent to GitHub. Request logs record method, path, status, duration and trace ID. App logs are untrusted output; assistants should treat them as data.

Credits and quotas for developers

Declare branch reservations in Git and use the account wallet to track and fund them.

Reserve resources for each branch

This guide describes credits billing. In this mode, the account’s Wallet replaces the plan billing page. The GitHub account shares a wallet across its repository orgs; each branch space has its own resource reservation.

Declare quotas in .inferra/org.yaml on the default branch. A feature branch cannot raise its own quota. For example:

version: 2
apps:
  - folder: api
    branches: [main, staging, "feature/*"]
quotas:
  main:
    cpu: "1"
    memory: 2Gi
    storage: 20Gi
  staging:
    cpu: "0.5"
    memory: 1Gi
    storage: 5Gi
  feature/*:
    cpu: "0.25"
    memory: 512Mi
    storage: 2Gi

Each matching feature branch gets its own quota, the most it can reserve, and pays for what it actually reserves. Two open feature branches mean two reservations. Branches without quota entries use platform defaults. Read the file reference for branch matching and resource fields.

Understand the cost

You pay for what your apps and services reserve, charged every hour at 1/730 of the monthly price. The quota is the most a branch can reserve; it is not the price.

ResourcePriceCharged by
CPU$16.19 per vCPU a monthReservation
Memory$1.78 per GB a monthReservation
Storage (Postgres disks, bucket size, service disks)$0.104 per GB a monthReservation
Postgres backups$0.0299 per GB a month; free for free accountsMeasured hourly

What counts as reserved: each app’s CPU and memory times its maximum instances, plus each service’s declared size. Postgres, the cache and custom services reserve CPU, memory and storage; a bucket reserves its storage size only, and that size is also its write limit. Bandwidth, S3 requests and build minutes are not charged.

Example. Branch main runs app api (250m CPU, 512Mi, up to 2 instances), app worker (250m, 256Mi, 1 instance), Postgres db (250m, 256Mi, 10Gi) and bucket uploads (20Gi). It reserves 1 vCPU, 1.5 GB memory and 30 GB storage:

CPU      1    x $16.19 = $16.19
Memory   1.5  x  $1.78 =  $2.67
Storage  30   x  $0.104 = $3.12
                         ------
                         $21.98 a month (about 3 cents an hour)

A preview branch feature/login with one api instance and a default Postgres reserves 0.5 vCPU, 0.75 GB and 1 GB: $9.53 a month, only while the branch exists. With 5 GB of backups ($0.15) the account pays about $31.66 a month. The bucket costs its full 20 GB even when it holds less.

In the dashboard, open Wallet → Space quota calculator to price a branch with the live rates, then copy its YAML into org.yaml.

Using Inferra without buying credits

Every account gets $5 of usage free each month, shared across all of its repositories; a card on file is required and is never charged unless you buy credits. Without credits, everything the account reserves must cost $5 a month or less, roughly one small app (0.25 vCPU and 256Mi is $4.50) plus a few GB of storage. Postgres backups are free for accounts that have never bought credits.

Read your wallet

Open the account’s Wallet from the dashboard navigation. It shows credit balance, free allowance left this month, monthly run rate, days of runway and a ledger of dated entries and amounts. Runway estimates how long the balance lasts at the current reservation rate.

The credits policy provides $5 of free usage each month per account, shared across its repos. The free allowance is used before paid credits. A card on file is required; one card receives one free allowance.

Add credits

In Wallet, enter an amount in USD and choose Add credits to open checkout. Under Auto top-up, enable it, set the balance threshold and amount to add, then choose Update auto top-up. Auto top-up is optional and off by default; the form defaults to adding $25 below $5. There is no top-up command in the captured CLI help.

Two checks before anything grows

Every push that raises a reservation passes two checks. If either fails, the commit check on GitHub fails with the reason and everything already running stays as it is. Lowering a size is always allowed.

  1. Quota (per branch). Everything the branch reserves, apps and services together, must fit its quota for CPU, memory and storage. Example: a 1Ti bucket on a branch with storage: 50Gi is refused. A quota lowered below what the branch already reserves is refused too.
  2. Wallet (paid ahead, per account). Accounts with paid credits need at least seven days of credit at the new monthly total. Accounts without credits need a card on file and a total of at most $5 a month. Example: raising the account from $31.66 to $136.08 a month needs $31.32 of credit; with $50 it is accepted, with $20 it is refused.

When billing is unavailable, increases are refused and decreases still apply.

When credits run out

Under the credits policy, at $0 new deploys pause immediately. After a three-day grace period, workloads pause. Data is kept for seven days; top up to resume. The core API enforces the wallet state returned by the billing service; grace timing and retention are handled by that service. Keep the wallet funded rather than relying on the retention window.

Inspect usage from the CLI

inferra target shop/main
inferra usage
inferra usage --json

In credits mode, output starts with the wallet balance, free allowance remaining and, when available, days of runway. The table shows each space’s reserved and used CPU, memory and storage, plus its monthly price. Example values:

Wallet: $50.00 balance, $5.00 free left, 27.9 days runway
SPACE      CPU RESERVED / USED  MEMORY RESERVED / USED  STORAGE RESERVED / USED  MONTHLY PRICE
shop/main  1 / 0.5              2Gi / 512Mi             20Gi / 5Gi               $60.00

A missing wallet is shown as Wallet: unavailable. Missing rates produce unavailable prices; missing reservations show unspecified. --platform is operator-only. See the CLI reference.

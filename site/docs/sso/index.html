Adding SSO to your app

Your app signs its own users in, with any library or identity service you like. Inferra gives it a stable HTTPS address, outbound access to the identity provider, secrets and a shared session store.

What works today

MethodHow
OAuth 2.0 / OpenID Connect
Google, Microsoft Entra ID, Okta, Auth0, GitHub, Keycloak…		Any OIDC library in your app (for example Passport, Spring Security, Authlib, NextAuth), or a hosted service such as Auth0, Clerk or Okta.
SAML 2.0A SAML library in your app, or an identity service that turns SAML into OpenID Connect for you.
LDAPLDAPS (port 636) to a directory reachable on the public internet. Private, office-only directories are not reachable yet.

Set it up

1. Register your app with the identity provider

Use your app's address, shown on its commit check and in the dashboard, as the redirect (callback) URL, for example https://YOUR-APP-ADDRESS/auth/callback. Each preview branch has its own address: register the ones you need, or use a separate client for previews.

2. Keep the client ID and secret out of your code

Put the client ID in a GitHub Environment variable and the client secret in the app's Secrets in the dashboard (or send it from GitHub with inferra init --secret NAME; see setup, step 4). Your app reads both from its environment.

3. Tell your framework it runs behind HTTPS

Inferra's gateway terminates HTTPS and forwards plain HTTP to your app on $PORT, with X-Forwarded-Proto: https. Turn on your framework's "trust proxy" setting so redirect URLs and secure cookies use https://; otherwise the identity provider rejects the callback.

4. Share sessions between instances

With more than one instance, keep sessions in a shared store. Declare a cache next to the app in org.yaml and point your session library at the URL Inferra injects (see the org.yaml reference), or use signed, stateless session cookies.

5. SAML certificates and keys

Store the certificate and private key as secrets (multi-line values are fine). If your library needs file paths, write them to a temporary file at startup; first-class secrets-as-files is coming.

Coming later

  • Your own domain (for example login.acme.com) for enterprise SAML setups that require it.

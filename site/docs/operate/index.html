Operate your apps

Git declares your apps and resources. Use the dashboard and CLI to operate the workloads already running.

Git owns what you declare; the dashboard and CLI operate

For GitHub repositories, change declarations in Git and push. The API refuses direct edits with managed by .inferra/org.yaml, followed by the repository or GitHub Environment to edit. The message names org.yaml even when a v2 setting lives in a branch file.

  • Apps and branches: declare app folders and eligible branches in .inferra/org.yaml. Git creates apps and branch namespaces; direct app/namespace creation, deletion and source deployments are refused.
  • Resources: declare services and their sizes and branch quotas in org.yaml. Declare app service bindings in the branch file. Manage service lifecycle and membership through those declarations.
  • Instances: set run.instances, run.cpu and run.memory in the branch file. Direct scaling is refused.
  • Members: edit org.yaml members; GitHub repository admins also have owner access. Direct member edits are refused.
  • Environment values: v2 files can declare org, branch and app environment maps. GitHub Environment variables are also synchronized. For GitHub-owned values, use GitHub → Settings → Environments → the original branch name. Direct environment writes are refused.

Secret names belong in the branch file; secret values can be written through the dashboard or the selected-secret GitHub workflow. Read the configuration reference and secret setup.

Choose the app

In the dashboard, open the repository org, its branch namespace, then the app. CLI examples below use an app folder named api. Set the target first:

inferra login
inferra target shop/main
inferra apps
inferra apps status api

Scale by changing the branch file

Open the app overview and choose Scale app. For a GitHub org, the current dialog says scaling is managed by org.yaml; it does not link to a GitHub line. Open the repository yourself and edit .inferra/main.yaml for main:

apps:
  api:
    run:
      instances:
        min: 2
        max: 2
      cpu: "0.5"
      memory: 512Mi

Commit and push that branch. Make sure the org.yaml quota covers the reservation. Autoscaling is not active; max does not turn it on. There is no scaling command in the captured CLI help. Inspect the result with inferra instances api.

Roll back an image

In the app overview, choose Roll back for the previous deployment, or open Deployments and choose Roll back on an earlier deployment that went live.

inferra deployments api
inferra rollback api
inferra rollback api --to DEPLOYMENT_ID

Rollback redeploys the earlier image. It keeps the current runtime configuration, environment and secret values; it does not restore an old configuration or database. The next eligible push deploys from the pushed commit again, subject to build selection and validation.

Promote the tested image

Promotion deploys the same image in another namespace without rebuilding, using the target app’s environment and secrets. Both namespaces must be on the same cluster; the source deployment must have gone live, and you need developer access to both namespaces.

The dashboard has Promote from… and Promote source → target controls in the earlier app view. The current tabbed app view does not expose these controls; use the CLI:

inferra promote api --from staging --namespace main
inferra promote api --from staging --to main --deployment DEPLOYMENT_ID

Restart, stop and start

Use the app header’s Restart or Stop button. A stopped app shows Start. Restart uses the same image. Stop removes running instances while keeping the URL, configuration and services. These operations require developer access.

inferra restart api
inferra stop api
inferra start api

Set secrets and inspect names

Open the app’s Settings tab. Under Secrets, choose Set value for a missing value or Replace for an existing value. The dashboard requests a restart so running instances receive the new value. Declare runtime secret names in the branch file. Values are never returned by secret read APIs.

The captured CLI lists names but has no secret-value write command:

inferra env api
inferra env api --reveal
inferra secrets api

--reveal requires developer access and reveals only ordinary environment values. Managed-service connection values remain hidden. Settings lists environment and secret names.

Logs, metrics and exec

Open the app’s Logs or Metrics tab. See Metrics and logs for chart and live-log controls. The current dashboard has no exec terminal; use the CLI to run a command in a ready instance:

inferra logs api --follow
inferra metrics api --since 6h
inferra exec api -- sh
inferra exec api --pod POD_NAME -- printenv PORT

Exec requires developer access. Without --pod, the CLI selects the first ready pod. Read the complete CLI reference.

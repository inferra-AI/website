org.yaml and branch file reference

Two short files in .inferra/: org.yaml declares apps, services, members and quotas; one file per branch describes how that branch builds and runs.

Two files, two jobs

Your GitHub account owns the credit balance. Each repository is an Inferra org; each eligible branch gets its own space on its first push. Apps are repository folders.

.inferra/
  org.yaml
  main.yaml
  staging.yaml
  feature.yaml

Inferra reads org.yaml only from the default branch. It reads the selected branch file from that branch’s pushed commit. A missing branch file uses platform defaults.

Example: .inferra/org.yaml

version: 2
build_unchanged_apps: false
env:
  LOG_LEVEL: info
apps:
  - folder: api
    branches:
      - main
      - staging
      - feature/*
    domains:
      main: inferralab.app
      staging: inferralab.run
  - folder: worker
    branches:
      - main
      - feature/*
services:
  postgres:
    - name: orders
      version: "17.2"
      cpu: "0.25"
      memory: 256Mi
      storage: 1Gi
  redis:
    - name: cache
      version: "7.4"
      memory: 512Mi
  bucket:
    - name: uploads
  rabbitmq:
    - name: queue
      image: registry.acme.com/mq/rabbitmq
      pull_secret: ACME_REGISTRY
      cpu: "0.5"
      memory: 1Gi
      storage: 5Gi
members:
  alice: owner
  bob: developer
quotas:
  main:
    cpu: "1"
    memory: 2Gi
    storage: 20Gi
  feature/*:
    cpu: "0.25"
    memory: 512Mi
    storage: 2Gi

org.yaml v2 fields

FieldMeaning
versionSet to 2.
build_unchanged_appsBoolean; false avoids rebuilding unchanged apps.
envMap of non-secret environment defaults shared by branches.
appsList of app declarations.
apps[].folderNamed relative repository folder; . is not accepted. The folder supplies the app name.
apps[].branchesList of exact branch names or patterns. Omit it to deploy only the repository default branch.
apps[].domainsMap of listed branch names to platform domain suffixes, such as inferralab.app or inferralab.run. Inferra generates the hostname. The development platform currently uses inferralab.dev.
servicesMap of service types to lists of declarations. Managed types: postgres, redis, bucket. Other types use an OCI image.
services.TYPE[].nameService name used by branch-file bindings.
services.TYPE[].versionQuoted managed-service version from the approved catalog; full versions are supported.
services.TYPE[].cpu / memory / storageExplicit resource sizes: CPU as a string, memory and storage as quantities such as 256Mi and 1Gi.
services.TYPE[].imageOCI image for a custom service type.
services.TYPE[].pull_secretName of a secret containing registry credentials. Values stay out of YAML and do not become app environment variables.
membersMap of GitHub logins to roles, such as owner or developer. Members sign in with GitHub and accept access.
quotasMap of branch names or patterns to cpu, memory and storage. Read from the default branch.

Branch selection and filenames

An exact branch match takes precedence over a pattern. main uses .inferra/main.yaml. A literal feature/special uses .inferra/feature/special.yaml. The pattern feature/* uses .inferra/feature.yaml, read separately from each matching branch’s commit. A pattern with no prefix uses .inferra/branch.yaml. Overlapping patterns resolve by longest match, then lexical order.

Space names are cleaned branch names, length limited, with stable hash suffixes where needed to avoid collisions. Deleting a branch removes its space asynchronously. Pattern branches delete their service instances immediately; named branches retain Postgres restore eligibility and bucket data for 7 days. Recreating a branch waits for cleanup.

Example: .inferra/main.yaml

Services, variables and secrets

Declaring a service does not provision it until an app binds it. Each branch gets its own instances. Apps on that branch may share a bound service; other branches cannot share that instance. Postgres supports backups and restore. The Redis-compatible cache has no persistent storage, backups or restore.

Custom services use private TCP endpoints from the image’s exposed ports. They run with gVisor and restricted permissions. One storage volume is mounted at the first image-declared volume, or /data if none is declared. Choose images compatible with these restrictions.

Environment precedence is app env, then branch env, then org env. Inferra also supplies PORT and bound-service variables such as ORDERS_URL, ORDERS_HOST and ORDERS_PORT. Only declared runtime secrets and automatic bound-service credentials reach each v2 app.

Files contain secret names, never values. Set values in the dashboard or use the selected-secret GitHub workflow. GitHub Environments use the original branch name, including slashes. Missing values are named on the commit check. Registry credentials are required separately. See secret setup.

Quotas and prepaid credits

Put branch quotas in org.yaml, alongside apps and services. Each branch matched by feature/* reserves and pays for its own quota. A branch without an entry uses platform defaults. A feature branch cannot raise its own quota.

Reserved CPU, memory and storage, plus metered bucket storage, backups and outbound bandwidth, are billed at simple per-unit prices. The first $5 every month is free per account, shared across its repos. A card on file is required and is never charged unless you buy credits. No plans or app limits.

The free allowance must cover the account’s total monthly reservation; paid credits must cover at least 7 days at a new total. A rejected quota change appears on the commit check and leaves previous quotas running. At $0, new deploys pause. After a 3-day grace period, workloads pause; data is kept for 7 days. Top up to resume. See pricing.

Validation rules

Both files use strict YAML parsing: unknown fields fail validation. Quote CPU and version strings, use named relative app folders, and use valid resource quantities and duration values. An app in a branch file must be declared and allowed on that branch in org.yaml. Every bound service must be declared there too. Managed versions must belong to the approved catalog. File-qualified errors and missing secret names appear on the commit check.

App builds use buildpacks. Node placement, privileged containers, host networking, sidecars and app volumes are not configuration fields; storage belongs to services. Do not carry v1 app fields into a v2 file.

Version 1 files

Version 1 files still work. inferra init currently generates v1; there is no automatic converter. To move to v2, use named app folders, put app branch lists and service resources in org.yaml, and move build/run settings, bindings, env and secret names to branch files. Push the default branch first, then eligible branches. Use the original branch names for GitHub Environments.

New spaces provision independent services and do not adopt v1 data. Allow capacity for both, export/import data or arrange support assistance, and verify the new deployment before removing old spaces.

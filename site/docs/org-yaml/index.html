org.yaml reference

The .inferra/org.yaml file declares an Inferra repository’s spaces, branch mappings, apps and service bindings. This reference covers every field accepted by the parser.

A complete starting point

This example is also used in the canonical setup guide.

version: 1
spaces:
  prod:
    branch: main
  stage: {}
  preview:
    branches: "*"
apps:
  api:
    path: .
    port: 8080
    command: node server.js
    cpu: "0.5"
    memory: 512Mi
    health: /health

Every accepted field

FieldTypeMeaning and example
versionintegerRequired: 1. Other versions fail validation.
build_unchanged_appsbooleanDefault false. Set true to build apps even when incremental comparison would skip them.
spacesmap of space names to objectsRequired, at least one. Example: prod: {branch: main}.
spaces.NAME.branchstringOne exact Git branch, e.g. main. A branch can feed only one space.
spaces.NAME.branchesstringPreview pattern, e.g. "feature/*". At most one preview space. Mutually exclusive with branch. * crosses slashes; ? matches one character.
spaces.NAME.membersmap of GitHub logins to role stringsExample: octocat: developer. Roles: viewer, developer, owner. Repository admins are owners automatically.
appsmap of app names to objectsMay be empty or omitted. Each non-empty entry declares an app; e.g. api: {path: .}.
apps.NAME.pathstringRepository-relative app folder. Empty, omitted or . means the root. Example: services/api. Cannot leave the repo.
apps.NAME.watchlist of stringsExtra changed paths that rebuild this app, e.g. [package-lock.json, "shared/"]. A trailing slash watches a directory; other paths match a file exactly. Root paths are refused; these are paths, not globs.
apps.NAME.buildobjectOptional buildpack selection and build-time variables. No Dockerfile field.
apps.NAME.build.buildpackslist of stringsAt most 8 unique catalog IDs, optionally id@version. Example: [nodejs]. Use inferra buildpacks for available IDs. IDs match lowercase letters, digits and hyphens, starting with a letter; maximum 63 characters. Optional versions are at most 128 characters, starting with a letter or digit, then letters, digits, dots, underscores, plus or minus.
apps.NAME.build.envmap of strings to stringsAt most 32 entries. Example: BP_NODE_RUN_SCRIPTS: build. Names match [A-Z][A-Z0-9_]{0,63}. Values are at most 1024 bytes. CNB_*, KPACK_*, PATH and HOME are reserved. Do not put secrets in this committed file.
apps.NAME.portintegerOmit or use 0 for the platform default, or set 1–65535; example 8080. The app must listen on the injected PORT.
apps.NAME.commandstringOptional start command, e.g. node server.js. The parser caps it at 4096 bytes. Otherwise use the buildpack’s launch command.
apps.NAME.cpustringExample "0.5", "2" or "500m". Non-negative numeric or integer millicore syntax; actual capacity is checked against the plan.
apps.NAME.memorystringInteger plus Mi or Gi; e.g. 512Mi or 2Gi. Plan limits also apply.
apps.NAME.replicasobjectOptional min and max instance counts; e.g. {min: 1, max: 1}.
apps.NAME.replicas.mininteger0 or greater; must not exceed max when both are set.
apps.NAME.replicas.maxintegerAt least 1; constrained by the plan’s instance limit.
apps.NAME.healthstringHTTP health path, e.g. /health. If non-empty it must start with /.
apps.NAME.domainsmap of space names to lists of stringsParser accepts prod: [api.example.com]. Custom domains are coming soon; do not use this to route traffic yet. Spaces must exist, preview spaces cannot have domains, hostnames must be lowercase with at least two labels, and duplicates are rejected.
apps.NAME.servicesmap of service names to objectsExample orders: {type: postgres, plan: shared-small}. Declaring the same service under another app binds that app too. The final declaration’s removal schedules deletion.
apps.NAME.services.NAME.typestringRequired. Parser requires a non-empty string; the platform service catalog decides what is available. Implemented managed types include postgres, redis (Valkey) and bucket.
apps.NAME.services.NAME.planstringRequired catalog plan. Example shared-small for Postgres, subject to account eligibility. The parser does not enumerate plans.
apps.NAME.services.NAME.versionstringOptional positive integer major, e.g. "17" for Postgres or "8" for Redis-compatible cache. Accepted only with type postgres or redis. The platform checks the live version catalog; omitted means its current version.

Names and validation

App, space and service names use 2–31 lowercase letters, digits or hyphens, beginning with a letter and ending with a letter or digit. GitHub member logins use at most 39 letters, digits or single internal hyphens. Branch names and patterns use at most 255 characters: letters, digits, dots, underscores, slashes, hyphens, plus * and ? for patterns. They cannot contain .., start or end with a slash, or end in .lock.

Unknown fields fail strict YAML decoding. Use quoted strings for CPU and service versions. A space can be {} when it is only a promotion target, but cannot be null. Invalid configuration is rejected before it is applied; catalog and plan checks happen on the server.

The file has no runtime env or secrets field. Use GitHub Environments and the documented secret-value paths. A syntactically accepted field is not a promise that a planned feature, such as custom domains, is live.

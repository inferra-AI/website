Your first deployment

Install the GitHub App, write org.yaml v2 and a branch file, then push. Inferra builds with buildpacks and reports the result on the commit. The CLI inspects and operates apps.

PrerequisitesConfigurationSecretsCommit checksPostgresTroubleshooting

1. Have a repository and its admin ready

You need Git, a GitHub repository you can push to, and a repository admin who can install the Inferra GitHub App. Organization policy may require an owner’s approval. Keep the app in a named folder such as api/; v2 does not accept the repository root as an app folder.

Please install the Inferra GitHub App on OWNER/REPO:
https://api.dev.inferralab.dev/v1/github/install
Please create GitHub Environments named after our branches,
and add MY_GITHUB_LOGIN as a developer in .inferra/org.yaml.
Setup guide: https://inferralab.com/setup/

2. Install the App and CLI

Install the GitHub App and choose your repository. Follow the CLI download and checksum instructions. Sign in with GitHub in the dashboard and create a personal token under Settings → Tokens, then paste it at the CLI prompt:

inferra login --api https://api.dev.inferralab.dev

The CLI saves this API address after login.

3. Create the app and the two files

inferra init --name api currently writes a supported v1 configuration, or write the two files by hand for v2 as shown here. Create api/package.json:

{
  "name": "inferra-first-app",
  "version": "1.0.0",
  "private": true,
  "scripts": { "start": "node server.js" }
}

Create api/server.js:

const http = require('node:http');
http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ ok: true }));
}).listen(Number(process.env.PORT || 8080), '0.0.0.0');

Create .inferra/org.yaml:

version: 2
apps:
  - folder: api
    branches:
      - main
      - feature/*

Download this org.yaml. Create .inferra/main.yaml:

apps:
  api:
    run:
      process: web
      port: 8080
    health:
      path: /health

Buildpacks detect Node from package.json. The example responds with HTTP 200 at /health. To use the same settings for feature/*, copy main.yaml to .inferra/feature.yaml. Each branch reads its own copy at its pushed commit. Without that file, Inferra uses defaults. Each matched branch gets independent apps and bound services.

Add members at the top level, for example members: {YOUR_GITHUB_LOGIN: developer}. Set quotas there too; see the two-file reference.

4. Set secret names and values

Create GitHub Environments named after the original branches: main, or feature/login including its slash. Declare secret names in the branch file, at branch or app level:

secrets:
  - API_KEY
apps:
  api:
    run:
      process: web
      port: 8080
    secrets:
      - JWT_SIGNING_KEY

Set encrypted values in the dashboard or in the matching GitHub Environment. The GitHub App cannot read secret values. For GitHub values, generate the selected-secret workflow for your existing v2 org file:

inferra init --workflow-only --force --secret API_KEY --secret JWT_SIGNING_KEY

Review the generated workflow before replacing an existing one. Only listed secrets leave GitHub; none are sent by default. Workflow-only generation understands v2 branch lists and patterns and selects the current branch’s GitHub Environment. Check its API URL is https://api.dev.inferralab.dev. Each app receives only its declared runtime secrets and bound-service credentials. Missing required values fail the commit check and name the missing secrets.

Put ordinary runtime defaults in org.yaml env or branch/app env. App env overrides branch env, which overrides org env. Never commit secret values.

5. Commit and push

Push the default branch first to establish org rules. For a repository whose default branch is main:

git add api/package.json api/server.js .inferra/org.yaml .inferra/main.yaml .inferra/feature.yaml
git commit -m "Configure Inferra app"
git push -u origin main

Then push eligible branches. Org rules always come from the default branch; branch settings come from the exact pushed commit.

6. Read the commit and open the app

Read configuration and app deployment checks separately. Configuration success does not mean the app is live. Invalid files and missing secrets appear on the commit check; failed builds and deployments link to their evidence. Unchanged apps can remain live without rebuilding.

inferra orgs
inferra target YOUR_ORG/main
inferra apps status api
inferra logs api
inferra logs api --follow

Replace YOUR_ORG with the name from inferra orgs. Open the live HTTPS address shown on the commit or by app status.

7. Add Postgres

Declare the service in org.yaml:

services:
  postgres:
    - name: orders
      version: "17.2"
      cpu: "0.25"
      memory: 256Mi
      storage: 1Gi

Download org.yaml with Postgres. Choose a version from the approved catalog. Under apps.api in each branch file that needs the database, add:

services:
  - orders

Commit org.yaml on the default branch and each binding on its branch. Every branch with that binding gets an independent database. Inferra supplies ORDERS_URL only to bound apps. Configure your Postgres client to use it; the HTTP example above does not query a database.

inferra services
inferra service status orders
inferra db logs orders
inferra env api

Removing the last binding schedules cleanup. Read retention and restore limits first.

Troubleshoot the deployment

ProblemWhat to check
Invalid configurationCheck the named file and field in the commit error. V2 needs named relative app folders, declared apps and declared service bindings. Unknown fields are rejected.
Missing secret valuesSet each named value in the dashboard or matching GitHub Environment, then run the selected-secret workflow if using GitHub.
No deploymentConfirm App access, valid org rules on the default branch and a matching app branch selection.
Failed build or health checkRead logs; check package.json, the Procfile process, the PORT listener and the health path.
Quota or credit rejectionReview branch quotas in org.yaml and add credits in Account → Billing.
Expired or revoked tokenCreate a new personal token and repeat login with the API address above.

Deploy your first app with config v3

Connect GitHub, add repo.yaml and app.yaml, set secrets and push. Add account services separately when you need them.

1. Prepare your repository

You need a GitHub repository you can push to and a repository admin who can install the Inferra GitHub App. An organization owner may need to approve it. A root app is supported; a monorepo can use api/ and worker/ folders.

Start with $15 of trial credit or 14 days, whichever comes first. Card required; one trial per card. Paid is $25/month including $25 of usage. Usage beyond that is extra; unused included usage does not roll over. Available to USA customers only for now.

Please install the Inferra GitHub App on OWNER/REPO:
https://api.inferralab.com/v1/github/install
Please grant our GitHub team developer access in .inferra/repo.yaml.
Setup guide: https://inferralab.com/setup/

2. Connect GitHub; optionally install the CLI

Install the GitHub App and choose the app repository. The CLI is optional for your first deployment: you can write the files below and use the dashboard. To use it, follow the download instructions, sign in to the dashboard, create a personal token in Settings → Tokens and paste it at the prompt:

inferra login --api https://api.inferralab.com

This is also the CLI’s default API address. An older saved login or INFERRA_API can override it. Never pass a token value as a command-line argument.

3. Add your app and config v3 files

For an existing app, inferra init writes v3: .inferra/repo.yaml, the app folder’s .inferra/app.yaml, and an optional GitHub environment-sync workflow. For api/, run inferra init --app-dir api. It does not create account.yaml. Review generated files before committing. Alternatively, use this complete small Node example.

Create api/package.json:

{"name":"first-app","version":"1.0.0","private":true,"scripts":{"start":"node server.js"}}

Create api/server.js:

const http = require('node:http');
http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ ok: true }));
}).listen(Number(process.env.PORT || 3000), '0.0.0.0');

Create .inferra/repo.yaml on the default branch. For the smallest setup:

version: 3

Create api/.inferra/app.yaml:

version: 3
name: api
type: web
port: 3000
health:
  path: /health

Buildpacks detect Node from package.json. This server answers /health with HTTP 200. Only the default branch runs with the minimal repo file. For a root app, put the app file at .inferra/app.yaml. Download the v3 repo starter.

4. Set secrets safely

Declare runtime secret names in repo.yaml or app.yaml; keep values out of Git. For example, add this to the app file:

secrets: [API_KEY]

Set the value in the dashboard or pipe it to the CLI:

printf %s "$API_KEY" | inferra secrets set api API_KEY

For optional GitHub sync, create GitHub Environments named after deployed branches, such as main and feature/login. The App cannot read GitHub secret values. Generate a workflow that sends only the selected secrets:

inferra init --workflow-only --force --secret API_KEY

Review the workflow before replacing one. Check that it targets https://api.inferralab.com. Each secret has one owner: GitHub-synced values are read-only in Inferra, and the workflow cannot overwrite Inferra-owned secrets. Remove a secret from its current owner before moving it. Missing values leave deployment waiting until supplied. Ordinary values resolve from repo env, repo branch env, app env, then app branch env, with later values winning.

5. Commit and push

For a default branch named main:

git add api/package.json api/server.js .inferra/repo.yaml api/.inferra/app.yaml
git commit -m "Configure Inferra app"
git push -u origin main

Repo rules come from the default branch. App settings come from the branch being deployed.

6. Check deployment and open the app

On GitHub, read inferra/config and inferra/deploy/api separately. Valid configuration does not mean the build is live. Use the dashboard’s app page for its address and deployment progress, or inspect it with the CLI:

inferra orgs
inferra target YOUR_ORG/main
inferra apps status api
inferra deployments api
inferra logs api --follow

Use the repository name shown by inferra orgs for YOUR_ORG.

7. Add account services

For account services, create a private GitHub repository named exactly <account>/.inferra and grant the Inferra GitHub App access. Put account.yaml and services/*.yaml at its root, not inside another .inferra directory. account.yaml is optional for a service-only setup. If present, list every connected app repository and provide all three quota values for the account and each repo.

For a Paid account, create services/orders.yaml in that private repository. This example attaches to application repository shop on main; replace both names with yours.

version: 3
name: orders
type: postgres
hosting: managed
size: db.t4g.micro
storage: 20Gi
engine_version: "17"
attach:
  shop:
    branches: [main]

Have a GitHub admin of the private account repository merge the service change first. Then add the binding to api/.inferra/app.yaml in the application repository:

version: 3
name: api
type: web
port: 3000
health:
  path: /health
services:
  orders: readwrite

Inferra supplies ORDERS_URL to the bound app. Never commit passwords. A binding grants access to an existing attached service; it does not create one. Multiple attached branches share the same data. For separate preview data, create a separately named service and attach it only to previews; data: shared does not create isolated data and is not available yet.

Trial accounts can use native Postgres, native Valkey and S3 buckets, but cannot use managed RDS. Native databases are rolling out; confirm availability with support@inferralab.com before depending on them. Custom image services are not available yet. SQS and DynamoDB on-demand are coming soon.

Previews and workers

To run previews, replace the minimal repo file with this, using your actual default branch name:

version: 3
branches:
  main: {}
  "feature/*":
    ttl: 7d
    quota: {cpu: 0.5, memory: 1Gi, storage: 2Gi}

A nonempty branches map must include the default branch if you want it to run. feature/* matches feature/login, but not feature/team/login. Preview apps have separate spaces; attached account services can share production data. Each preview adds usage and can exhaust trial credit faster. TTL expires a preview 7 days after its last accepted push. Branch removal does not delete account-owned managed services.

For a worker, create worker/.inferra/app.yaml with version: 3, type: worker and process: worker; omit HTTP port and health settings. See the v3 reference and billing.

Troubleshooting

No deploy? Check GitHub App access, accepted repo rules on the default branch and a matching branch entry. Invalid config? Read the named field in the commit status; unknown fields fail validation. Missing secrets? Supply each value through its owner. Failed health check? Check logs, the start command, 0.0.0.0 listener, PORT and health path. Quota or billing rejection? Review repo quotas and account billing. For help or restore requests, email support@inferralab.com.
